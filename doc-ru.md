# Group Chat Modes (Smart / Alias)

**Group Chat Modes (Smart / Alias)** — стороннее UI-расширение для SillyTavern, добавляющее в групповые чаты два дополнительных режима ответа: **Smart** (значение стратегии 4) и **Alias** (значение стратегии 5). Режим Smart отбирает отвечающих каскадом из пяти уровней — от прямого попадания по имени или алиасу через тихий запрос к нейросети, который решает, к кому обратились по признаку и у кого есть свой повод поддержать разговор, до контекстного авто-выбора по логике диалога при пустом вводе; если и там не откликается никто, в чат публикуется короткая заметка об этом. Режим Alias работает только по алиасам персонажей и вовсе не вызывает нейросеть. Документация описывает версию 1.3.3. v1.3.1 — исключение личности пользователя из всех уровней триггера/кандидатов, авто-удаление пустого сообщения личности, появляющегося при пустом вводе (фолбэк ядра ST 1.19.0), и уровень 5 — контекстный авто-выбор отвечающего по логике диалога при пустом вводе.

## Обзор

Расширение не патчит ядро SillyTavern. Оно добавляет в выпадающий список «стратегия ответа» (Reply strategy) в панели группы два пункта — **Smart** со значением 4 и **Alias** со значением 5. Самих этих значений ядро не знает, поэтому группы, для которых выбран один из новых режимов, целиком обслуживаются расширением: оно следит за событиями чата и само решает, кто из участников отвечает на сообщение пользователя. При этом в настройках расширений появляется своя панель (**Extensions → Group Chat Modes (Smart / Alias)**), а в панель группы — переключатель лимита отвечающих для конкретной группы.

## Режимы

**Smart (стратегия 4)** — «думающий» режим. Каждое сообщение пользователя проходит каскад из четырёх уровней (см. следующий раздел): сначала локальная проверка по именам и алиасам, и только если она ничего не нашла — один тихий запрос к нейросети, который ищет сразу и косвенные обращения, и тех, кому есть свой резон поддержать разговор. Как только отвечающие найдены, каскад останавливается. Если не нашлось никого, в чат уходит заметка «никто не откликнулся» (когда она включена в настройках).

**Alias (стратегия 5)** — режим без нейросети. Сообщение пользователя сверяется с алиасами персонажей: имя каждого персонажа проверяется всегда, дополнительно — перечисленные сигналы (прозвища, сокращения, формы обращения). Отвечают только те, для кого нашлось совпадение; обращений к LLM здесь нет вообще.

## Каскад уровней (режим Smart)

- **Уровень 1: прямое попадание (имя или алиас)** — локальная проверка сообщения по алиасам персонажей: имя персонажа учитывается всегда, плюс сигналы. Если нашлись участники, они отвечают сразу, и каскад останавливается. Нейросеть не вызывается.
- **Уровень 2: косвенный вызов (по признаку)** — когда прямых совпадений нет, тихий запрос к нейросети спрашивает, к кому обратились по признаку — профессии, роли, внешности (например, «Эй, пекарь!»), — вместо имени.
- **Уровень 3: кто мог бы поддержать разговор** — в том же единственном запросе дополнительно спрашивается, у кого прямо сейчас есть собственный повод поддержать разговор, даже если к нему напрямую не обращались.
- **Уровень 5: авто-выбор по контексту (пустой ввод)** — работает только в Smart и только при пустом вводе. Когда каскад дошёл до точки «никто» (тихий запрос уровней 2/3 никого не нашёл), один дополнительный тихий запрос спрашивает: «кто должен говорить следующим по логике диалога?» — по незавершённым ожиданиям, неотвеченным парам «вопрос — ответ», чья очередь подошла. Ответ должен называть ровно одного участника и сверяется строго со списком (точное имя или алиас, без нечёткого поиска): единственный ясный выбор заменяет заметку „никто не откликнулся“ ответом этого участника, любой другой исход оставляет прежнее поведение. Уровень включается отдельной галочкой в панели, по умолчанию включён; личность пользователя не выбирается никогда.
- **Заметка „никто не откликнулся“ в чате** — если Smart не выбрал никого, расширение отправляет в чат короткое сообщение пользователя: `(Никто не вступил в разговор.)` (в английском интерфейсе — `(Nobody joined the conversation.)`); язык выбирается одним вызовом `localize()`. Нейросеть не вызывается.

Нейросеть вызывается только в тихих запросах: уровни 2 и 3 — одним тихим запросом `generateRaw` к текущему активному API (пресеты при этом не затрагиваются), уровень 5 — отдельным тихим запросом и только при пустом вводе. Уровни 1 и 4 — локальные, а режим Alias не вызывает нейросеть вовсе. Если тихий запрос завершится ошибкой или вернёт пустой ответ, это считается «никого не нашлось»: уровни 2 и 3 просто пропускаются, исключение наружу не пробрасывается. Ошибка или пустой ответ запроса уровня 5 считается отсутствием ясного выбора.

## Лимит отвечающих (потолок)

Сколько участников может ответить на одно сообщение пользователя, ограничивается «потолком»:

- **значение по умолчанию** задаётся в панели расширения настройкой **Лимит отвечающих (по умолчанию)**: варианты 2, 3, 4, 5 и «нет»; хранимое значение 0 означает «нет» — без лимита; по умолчанию выставлен лимит 2;
- **для конкретной группы** — виджет **Лимит отвечающих (группа)** в панели самой группы: варианты «(по умолчанию)», 2, 3, 4, 5, «нет». Значение хранится в пользовательском поле группы `st_gc_modes.ceiling` и имеет приоритет над значением из панели расширения.

Если совпавших больше, чем позволяет потолок, лишние отсекаются; порядок совпавших сохраняется, а отсечённые участники логируются в консоль.

## Алиасы в карточке персонажа

Алиасы хранятся в самой карточке персонажа — в поле `character.data.extensions.st_gc_modes_aliases`, одной строкой через запятую (например, «Кир, Кирочка, печница»). Хранение в карточке переживает перезагрузку страницы и переустановку расширения, а алиасы остаются частью файла персонажа: карточка экспортируется и переносится вместе с ними.

В расширенной форме редактора персонажа есть поле **«Заменители имени (алиасы)»** (в английском интерфейсе — "Name aliases"): однострочный ввод списка через запятую, рядом кнопка **«Сгенерировать через LLM»**. Кнопка одним тихим запросом отправляет описание персонажа в активный API, разбирает ответ и подставляет собранный список алиасов в поле. Как и остальные поля редактора в режиме редактирования, это поле сохраняется автоматически ядра — на смене фокуса правка (в том числе полная зачистка поля) попадает в карточку, и после перезагрузки страницы видно именно её; кнопка Save по-прежнему тоже работает. Если модель не вернула ни одного кандидата, поле очищается, и пустота записывается в карточку тем же путём. В режиме создания нового персонажа поле пустое, а кнопка генерации выключена, пока персонаж не создан и не сохранён. Само поле (ручное сохранение) работает независимо от главного выключателя расширения; генерация выключателем ограничена.

Таблицы алиасов в панели настроек расширения больше нет. В панели остались: главный выключатель, ссылка на репозиторий, инструкции режиссёра, глубина контекста, включатели уровней 2/3/4 и лимит отвечающих по умолчанию — виджетов алиасов там нет.

Порядок разрешения алиасов одинаков для Smart и Alias:

- сначала проверяется поле в карточке персонажа;
- когда поле в карточке пустое, используются старые алиасы из настроек расширения (`aliasSignals` в `extension_settings['st-gc-modes']`) — резерв для уже настроенных групп; этот резерв работает только на чтение;
- имя персонажа целиком проверяется всегда, поверх любых алиасов — как и раньше.

Для новых настроек алиасы заводите в карточке персонажа. Старое хранилище считается устаревшим: ничего его больше не пополняет, но и не удаляет — данные в нём остаются, и их читает только резервный механизм.

Механика совпадений не изменилась:

- имя персонажа всегда проверяется само по себе — указывать его среди алиасов не нужно;
- многословный сигнал считается совпавшим, только если в сообщении есть все его слова;
- одиночное слово-сигнал совпадает только с целым токеном: «Кир» сработает на «Кир», но не на «Кирилл»;
- алиасы работают в обоих режимах — и в Smart, и в Alias.

## Панель настроек

Панель открывается в **Extensions → Group Chat Modes (Smart / Alias)**.

1. **Включено** — по умолчанию включено; главный выключатель. Когда выключено, расширение убирает пункты Smart/Alias из выпадающего списка «стратегия ответа» и виджет лимита группы из панели группы и перестаёт реагировать на сообщения — группы, настроенные на Smart или Alias, просто молчат, потому что ядро SillyTavern само не знает значений стратегии 4 и 5. Панель настроек при этом остаётся доступной; переключатель сохраняется штатным механизмом extension-settings, и его срабатывание подтверждается всплывающим уведомлением (toast).
2. **Smart: инструкции режиссёра** — редактируемое текстовое поле; заполняется блоком по умолчанию (см. ниже). Подсказка: «Системные инструкции тихого „режиссёрского“ запроса к LLM в режиме Smart, когда прямого совпадения по алиасам нет. Модель читает список участников и последние сообщения.»
3. **Глубина контекста N (последние сообщения)** — по умолчанию 10, диапазон 1–50. Подсказка: «Сколько последних сообщений чата видит режиссёрский запрос (1-50).»
4. **Уровень 2: косвенный вызов (по признаку)** — по умолчанию включено.
5. **Уровень 3: кто мог бы поддержать разговор** — по умолчанию включено.
6. **Уровень 5: авто-выбор по контексту (пустой ввод)** — по умолчанию включено. Подсказка: «Если сообщение пользователя пустое, а уровни 2/3 никого не нашли, сделать один тихий запрос: кто должен ответить по логике диалога? Один явно указанный участник отвечает вместо заметки „никто“. Личность пользователя не выбирается никогда.»
7. **Заметка „никто не откликнулся“ в чате** — по умолчанию включено.
8. **Лимит отвечающих (по умолчанию)** — по умолчанию 2; варианты 2, 3, 4, 5, «нет» (0).
9. Виджетов алиасов в панели больше нет. Алиасы задаются в расширенной форме редактора персонажа (см. раздел «Алиасы в карточке персонажа»).
10. **Лимит отвечающих (группа)** — в панели группы; варианты «(по умолчанию)», 2, 3, 4, 5, «нет» — приоритет над значением по умолчанию.
11. В верхней части панели размещена ссылка на репозиторий — <https://github.com/DarkLeopard/st-gc-modes> — с подписью «Подробности — в README».

Текст инструкций режиссёра по умолчанию (из `DEFAULT_SMART_INSTRUCTIONS` в index.js):

```
You are the group-chat director choosing which characters join the conversation.
You receive: participant list (name + short description), recent chat, and the last user message.
Pick ONLY participants who would realistically respond:
1. They were addressed by an indirect sign instead of their name (their profession, role, place, or a personal attribute from their description).
2. They have their own motivation, reason, or duty to chime in right now.
Do not pick anyone out of politeness. If several fit, list all. Answer format: participant names separated by commas, copied exactly as given in the list. If no one fits, answer exactly: none.
```

## Поведение в чате

- Каскад реагирует только на сообщения пользователя: триггером служит событие отрисовки пользовательского сообщения (`USER_MESSAGE_RENDERED`). Сообщения, отправленные самими персонажами (self-calls), каскад не запускают.
- Заметка «никто не откликнулся» — это обычное сообщение пользователя: последующие запросы к нейросети видят её в контексте чата.
- Повторное срабатывание на одно и то же сообщение исключено: события дедуплицируются по чату, индексу сообщения и дате отправки.
- Каскад запускается с небольшой задержкой (50 мс) и дожидается, пока группа свободна (idle).

Пустая отправка — особый случай. В SillyTavern 1.19.0 группа со стратегией Smart (4) или Alias (5) при пустом поле ввода уходит в фолбэк ядра «отправить сообщение пользователя как есть»: в чат попадает пустое сообщение, названное именем личности пользователя. Расширение убирает его сразу после отрисовки. В Smart это считается сигналом продолжения, каскад запускается с пустым вводом: когда логика диалога ясно указывает следующего говорящего, отвечает именно этот участник (уровень 5); если ясного продолжения нет, всё идёт по прежним правилам — вплоть до заметки «никто не откликнулся». В Alias сигналов нет и ничего не происходит. Личность пользователя в качестве отвечающей не выбирается ни на каком уровне, а её собственные сообщения расширение не трогает.

## Ограничения и известные нюансы

- После обновления ядра SillyTavern DOM-инъекция может перестать работать, пока расширение не подгонят под изменившиеся идентификаторы элементов.
- Модель с «рассуждениями» (reasoning model) может вернуть пустой ответ на тихий запрос — тогда расширение считает, что «никто не откликнулся»; лечится подстройкой промпта.
- Алиасы совпадают по целым словам, а не по подстрокам.
- В режиме создания нового персонажа алиасы недоступны до первого сохранения: поле пустое, кнопка генерации выключена — это следствие хранения алиасов в карточке.
- Тихий запрос отправляет свежий контекст чата на активный API — это затрагивает приватность и стоит токенов.

## Установка, обновление, переустановка

**Установка.** В SillyTavern откройте **Extensions → Install extension** (иконка-пазл / кнопка «Install extension»), вставьте URL репозитория `https://github.com/DarkLeopard/st-gc-modes`, выберите **for me only** («только для себя») и перезагрузите страницу (F5).

**Обновление.** Откройте **Extensions → Управление расширениями** (Manage extensions): в строке расширения появляется кнопка обновления (иконка загрузки, подсказка «Update available»), когда в репозитории выходит более новая версия. Обновление применяется сразу, без подтверждения. У версии 1.2.0 автообновление выключено — нажимайте кнопку вручную; сама процедура обновления не меняется. После обновления таблицы алиасов в панели не будет, а прежнее значение алиасов из настроек сохраняется и продолжает работать как резерв (см. раздел «Алиасы в карточке персонажа»). Если кнопка не появилась, удалите расширение и установите заново тем же путём: настройки (включённость, инструкции, старое резервное значение алиасов) при переустановке сохраняются, потому что хранятся в пользовательских настройках, а не в папке расширения; алиасы в карточках персонажей тоже остаются на месте.

**Переустановка / чистая установка.** Удалите старую папку через UI расширений (**Uninstall** / **Remove**), затем установите расширение по URL ещё раз.

Расширение собрано и проверено на SillyTavern 1.19.0+; это обычные ES-модули — ни шага сборки, ни npm-зависимостей.
